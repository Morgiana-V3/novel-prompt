# Skill 使用总则

> 本总则固定生效、不可关闭，只规定你如何找到并使用用户启用的 Skill，以及多份 Skill 冲突时怎么取舍。具体怎么写、怎么读提示词，由下方启用的 Skill 决定。

## 1. 找到要用的 Skill

- 下方「已启用的 Skill」清单列出了本次任务要使用的全部 Skill：**优先级**、名称、说明、适用模型。清单由用户在软件里选择和排序，已经按当前功能和目标模型筛选过，没有出现在清单里的 Skill 一律不用。
- 每份 Skill 的正文按优先级从高到低依次附在清单后面，以 `<skill priority="N" name="…">` 开始、`</skill>` 结束。
- 动手前先**通读全部 Skill**，弄清每份覆盖哪些方面（例如：一份管 tag 挑选和编排，另一份只管画风偏好）。
- 工作台可能同时提供多个作用范围（scope）的 Skill。依据本轮用户任务应用相关条款：讨论、编写提示词、检查画面和局部重绘各有用途；不能因为清单中存在某份 Skill，就自动执行对应功能。没有启用的文档不能作为隐藏补充规则。
- Skill 中标注【V4.5】/【V5】的内容只在对应目标模型下使用，另一版本专用的内容忽略；未标注的两者通用。
- 清单为空时，按你对 NovelAI 与 Danbooru 的通用知识工作。

## 2. 优先级与冲突

1. **用户在本次请求中明确提出的要求**最高，高于所有 Skill。
2. Skill 之间：**priority 数字越小，优先级越高**。两份 Skill 对**同一件事**的要求不同时，以优先级高的为准，优先级低的那一条在这件事上不执行。
3. 冲突**按具体事项**判断，不按整份判断：一份 Skill 在某一点上被覆盖，不影响它其他规则的效力。
4. 不冲突的规则**互相补充**：高优先级 Skill 没有涉及的方面，照低优先级 Skill 的规则做。
5. 判断是否冲突时看实际效果：一份要求「负面越短越好」、另一份要求「负面必须包含某组 tag」，只要能同时满足就都执行；无法同时满足才按优先级取舍。
6. 同一份 Skill 内部前后矛盾时，以更具体的说法为准；仍无法判断时以靠后的为准。
7. 因为优先级放弃了某份 Skill 的规则时，在依据（evidence）里写明，例如「按 Skill《我的风格》，未采用《内置 · 提示词编排》的 xxx」。

## 3. Skill 不能改变的约定

Skill 正文之后还会给出「程序约定」（外部 agent 看到的是「使用说明」），它是软件解析、校验和生图所依赖的格式，**优先于所有 Skill**：输出格式与字段、tag 必须真实存在、`Text:` / 互动前缀 / 位置等写法。某份 Skill 的要求与程序约定矛盾时（例如要求换一种输出格式、用自然语言写位置），按程序约定执行，忽略该条要求。

## 4. 引用依据

在 evidence 中引用 Skill 时写出名称，例如「Skill《内置 · 提示词编排》第 5.3 节【官方】」「Skill《我的风格》」。只写"第 X 节"会对不上是哪一份。

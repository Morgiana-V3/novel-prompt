# Skill 文档组织与加载

三份内置规则使用 `skills/<名称>/SKILL.md` 管理；大篇资料放在 `references/*.md`，`core.md` 继续固定加载。`builtin:prompt`、`builtin:preview`、`builtin:inpaint` 标识、启用状态和顺序保持稳定；用户自己的 Skill、副本和已提交讨论的冻结快照不自动重写。

## 内容组织

| Skill | 入口保留 | 参考文件 |
| --- | --- | --- |
| 提示词编排 | 职责、保真与工具校验、基础语法、编排顺序、依据分类和输出要求 | 一致性检查、角色与文字、负面与模型、风格与统计、组合示例（共 5 份） |
| 画面推测 | 全部常用规则，包括角色区域、负面误伤与证据边界 | 无需补读 |
| 局部重绘 | 工作边界、遮罩与强度、字段归属、语法文字、最小修改与输出契约 | 仅歧义示例 |

按共同使用场景安排参考文件，不为每个小标题单独拆文件。同级标题与规则清单不使用编号，引用使用主题名；只有明确要求按固定顺序排列的内容使用有序列表。型号、权重、坐标、优先级和漫画格位等有实际含义的数字保留。

有参考文件的入口定义读取条件，命中多个条件时合并读取；完整方案不等于必须加载完整范例。局部改句与评估按任务范围处理，不自动启动整套查词和重编排。画面推测所需的负面冲突规则放在本包，避免隐式依赖未启用的编排 Skill。

## 读取接口与快照

内置 AI 使用 `read_skill_reference(id)` 读取本轮冻结正文，也支持 `ids` 数组批量读取；工作台外部 Agent 使用 `get_workspace_context(skills_ids: [...])`。非工作台场景使用 `get_skill(id, resource)`。`skills_task:all` 显式返回所有正文，普通任务不应默认使用它。

`get_skill` 输出契约同时接受入口 `{id,name,content}` 与资源 `{id,path,content}`。同一消息链共享已读取状态，正文不重复注入；读取受整体预算约束，不能在业务循环中重新计算一套预算。

`missingRequiredIds` 检查入口与显式请求的资料，不能自动判断语义场景。参考资料的读取条件仍由 AI 执行；读取失败或正文已离开当前上下文时，需补读或说明缺失，不能把目录当成正文。查询预算结束后应根据现有证据作答，说明未核实内容，不自动生图。

## 随附黑白漫画模板

`skill-templates/nai-manga-prompt-design/` 独立于 `skills/`，随安装资源发布；不直接加入内置规则、启用列表或初始上下文。用户通过「随附场景模板」查看并复制，副本默认关闭。已有用户副本保持原样，使用更新后的模板需重新复制并选择启用。

模板包含输入组织与评估、动作与连续性、格框、镜头、黑白画法与线效、文字与对白、完整示例共 7 份参考资料。技法索引放在对应主题中，不附加 customize 指南或定制教学。

随附模板支持从个人目录删除，删除选择写入用户设置，后续升级不重新添加；安装资源由安装器维护，不直接删除安装目录文件。

## 维护边界

拆分用于减少无关内容加载，不保证每个任务的累计 token、费用、耗时或输出质量改善。合并文件也不保证减少模型往返，因为多份资料可以一次批量读取。短规则可直接提供，长资料按需读取，粒度应依据实际共用场景调整。

内容保全、包内链接、稳定标识、复制导出、冻结读取与 MCP 输出契约由现有测试覆盖，入口见 [验证说明](testing.md)。真实模型的场景选择、最终字段保真和画面质量需要另外验收，不能用可解析响应或离线字符数替代。

测试报告、截图、原始响应、规则对照快照与运行日志统一保存在项目外；本文件只维护当前设计，不累积历次执行结果。

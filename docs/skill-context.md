# 内置 Skill 按场景读取

三份内置规则使用 `skills/<名称>/SKILL.md` 管理；大篇资料另放 `references/*.md`，`core.md` 继续固定加载。原有 `builtin:prompt`、`builtin:preview`、`builtin:inpaint` 标识、启用状态和顺序保持不变；用户自己的 Skill、副本和已提交讨论的冻结快照不重写。

## 分层方式

| Skill | 入口保留 | 参考文件 |
| --- | --- | --- |
| 提示词编排 | 工作流程、保真与工具校验、基础语法、编排顺序、依据分类和输出要求 | 冲突检查、角色与互动、模型专用词、语言与文字、负面、画师与统计、示例 |
| 画面推测 | 全部常用推测规则，包括角色区域、负面误伤与证据边界 | 无需补读 |
| 局部重绘 | 工作边界、遮罩与强度、字段归属、语法文字、最小修改与输出契约 | 仅歧义示例 |

有参考文件的入口定义读取条件，命中多个条件时合并读取；完整方案不等于必须加载完整范例。原编号沿用，画面推测中关于确定性、未指定内容和引用数的表述已依据真实验收修正，修订指纹独立记录。画面推测所引用的负面冲突表已放入本包，避免隐式依赖未启用的编排 Skill。

内置 AI 使用 `read_skill_reference(id)` 读取本轮冻结正文；工作台外部 Agent 使用 `get_workspace_context(skills_ids: [...])`。非工作台场景使用 `get_skill(id, resource)`。`skills_task:all` 仍显式返回所有正文，普通任务不应默认使用它。

`missingRequiredIds` 检查入口与显式请求的资料，不能自动判断语义场景。参考文件的读取条件仍由 AI 执行；正文读取失败或已离开当前上下文时，需补读或说明缺失，不能把目录当成正文。

## 随附漫画场景模板（2026-10-28）

`skill-templates/nai-manga-prompt-design/` 独立于 `skills/`，随安装资源发布；不加入内置规则、启用列表或初始上下文。用户通过「随附场景模板」查看并复制，副本默认关闭。旧的用户单文件与当前启用状态保持原样，切换时需手动关闭旧版、启用副本。

原稿正文 44,613 字符，模板现为短入口与 13 份黑白漫画场景参考资料，保留原有专项内容与完整实例；已移除 customize 指南及入口中的定制教学说明。原稿个人画风与参数改为可替换示例，修正了原单文件的锚点链接；92 个代码块完整保留。

初版（尚含 customize 指南）仅启用漫画副本、其他 Skill 关闭、V5 工作台的离线对照：使用相同总则、清单和包裹格式，原单文件首轮 46,705 字符，拆分后入口加参考目录首轮 4,608 字符，约减少 90.1%。这不是 token 或模型总请求大小，也不是所有用户当前配置的减少比例。未复制启用时，模板不会增加 Skill 上下文；复杂场景仍会按需补读，累计量与实际读取路径有关。

`node scripts/check.mjs skills:templates skills` 覆盖只读隔离、默认关闭、复制/导出、冻结补读、引用与标题跳转、原稿例句保留、安装路径模拟和真实界面交互。已通过构建、类型、lint、样式与边界检查；本次没有生成或安装新的发行安装包，当时尚未用真实模型验证场景选择和画面质量。


## 调度优化与真实前台验证（2026-10-28）

用户当前启用的漫画规则仍是旧的 44,613 字符单文件。通过运行中的开发版前台 MCP，在独立诊断会话提交「胡桃与芙宁娜战斗、五格、出格/插格、蒙太奇、对白」请求，约 55 秒重现「本轮工具调用过多」。原代码在单次回复超过 8 个标签工具调用、或查询轮数耗尽时直接报错；此前没有细分调度日志，不能确定那次具体命中了哪个分支。

修复后：参考读取支持 `ids` 数组（每次最多 16 份，兼容单个 `id`）；同一消息链共享读取状态，正文不重复注入。最多 8 轮资料读取、48 份资料后收束，不再在业务循环每次重置。标签查询最多 4 个并发，同参数调用复用结果；保留每轮讨论 48 次唯一查询与 6 轮查询预算，结束后停止查询并要求根据现有证据作答。预算未覆盖的内容必须说明未核实。取消仍中止请求、释放会话锁，不自动生图。聊天区显示理解需求、核对提示词、整理或汇总方案的真实阶段；消息诊断保存请求/读取/缓存计数和总耗时，不保存凭据或额外思考正文。

更新后的源码在独立临时 profile、正常可见窗口中通过前台 MCP 调用真实配置的 deepseek-flash，启用拆分后的漫画副本和三份内置规则。相同需求约 81 秒返回可审核的完整方案，没有执行生图：7 次模型请求，2 次参考读取调用合计 15 份资料，7 次标签查询调用；正常结束，没有触发截断错误。首轮请求消息约 24,052 字符，复杂场景补读和查询后最后一次消息约 114,221 字符（包含协议、结果和供应商返回的上下文，不是 token 计数）。这次验证说明调用链能完成任务，不能据此宣称提速、所有场景都不会耗尽预算，或画面质量已经验证。

原会话、原 Skill 与设置未改动；在开发版另建了独立诊断会话，旧宿主没有被强制重启。源码变更需重启开发版加载。随附模板支持从个人目录删除，删除选择写入用户设置，后续升级不重新添加；安装资源本身由安装器维护，不直接删除安装目录文件。

## 验收后的优化（2026-10-28）

采用混合加载：画面推测短规则一次提供；局部重绘的遮罩、强度、文字与预设规则直接提供，仅示例按需读取。提示词编排与漫画长资料继续按实际改动读取，单处改句/评估不自动启动整套查词和重编排。漫画要求保留跨格身份关系，并对照最终字段检查取景、左右、接触点与对白归属。旧用户副本和已冻结讨论保持不变，使用新版漫画需重新复制随附模板后切换启用。

`get_skill` 输出契约现在同时接受入口 `{id,name,content}` 与资源 `{id,path,content}`。桌面测试通过真实 stdio MCP 调用覆盖入口、总则、参考文件和缺失路径，避免仅调用工具函数漏掉输出校验。优化、推测和工作台使用已有 JSON 输出选项，并保留本地解析与修复检查。

当前离线首轮 Skill 字符数（V5，仅三份内置启用）：优化 9,510、推测 7,460、重绘 7,368、工作台 20,469。推测入口较旧单文件更大，因为补齐负面知识和证据边界；目标是省去为短规则专门往返的请求，而非强求首轮文本最短。

真实复测使用 deepseek-flash（low）、相同六个输入和隔离 profile：六项首测，修订推测边界与范例触发后再测三项，共 9 次任务、31 次模型请求，均结束且无 JSON 格式重试。最后一次结果对比此前拆分版：累计输入在单人优化/负面推测/精确文字/局部改句/五格漫画/去字策略分别变化 −11.5% / −49.8% / −15.3% / −34.9% / −6.6% / −34.1%。这是小样本对照，不是费用或耗时保证；五格漫画第一轮输入反而上升，最终轮仍有互动前缀、接触点与未知词问题，去字策略仍会补充缺乏依据的参数范围，画面推测也残留过度推断。所有输出仅供人工审核，未生图。

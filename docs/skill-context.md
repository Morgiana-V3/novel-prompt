# Skill 文档组织与加载

三份内置规则各自使用 `skills/<名称>/SKILL.md` 完整提供执行规则，`core.md` 继续固定加载。仅编排的组合范例保留在 `references/examples.md`。`builtin:prompt`、`builtin:preview`、`builtin:inpaint` 标识、启用状态和顺序保持稳定；用户自己的 Skill、副本和已提交讨论的冻结快照不自动重写。

## 内容组织

| Skill | 入口保留 | 参考文件 |
| --- | --- | --- |
| 提示词编排 | 执行流程、任务边界、一致性、角色与文字、负面与模型、风格与统计、语法与输出复核 | 组合示例（1 份，不承载独有的必需规则） |
| 画面推测 | 全部常用规则，包括角色区域、负面误伤与证据边界 | 无需补读 |
| 局部重绘 | 执行流程、工作边界、遮罩与强度、字段归属、语法文字、最小修改、输出契约与四组示例 | 无需补读 |

三套职责保持分开，核心规则不再由 Agent 决定是否补读。每套都有明确的编号执行流程；编排另保留提示词排列顺序。并列主题与规则使用无序列表，引用使用主题名及可验证链接，不恢复数字章节引用。型号、权重、坐标、优先级和漫画格位等有实际含义的数字保留。

完整规则加载不等于扩大任务范围：创建、整体优化、最小修改和仅评估分别应用对应条件，不自动启动全套查词和重编排。完整方案不等于必须加载完整范例；仅在索要范例或结构仍有歧义时补读组合示例。预览与重绘各自包含所需的字段和解析约束，不隐式依赖未启用的编排 Skill。

准确性优先于上下文体积。规则适用范围同时检查输入与本次将交付的字段：空白输入创建完整方案也必须应用一致性、角色/文字、负面/模型等规则。场景模板和用户目录包仍按各自条件补读；模板示例不能替代内置完整正文。三套核心规则通过现有入口加载链路一次交付，不需要新增加载开关。

合并必须同时迁移链接、调用方与验收。已合入正文的旧资源不再列入当前目录，主题采用页内锚点；旧冻结快照仍使用其保存的正文与索引，不替换成当前文件。无序规则并不表示可选，有序流程也不允许跳过保真与最终核对。

交付核对以实际字段为准：原稿中的明确内容不因未在附加要求中重复而失效；画面左右与手别、物件身份与数量分别保留；对白原文和归属、主格与同刻插格接触点、说明与字段保持一致。已核实 tag 可复用，未知词不能通过删除用户语义来消除警告。没有原稿或成图时，策略保持条件式，不把候选片段说成已完成的修改。

## 读取接口与快照

内置 AI 使用 `read_skill_reference(id)` 读取本轮冻结正文，也支持 `ids` 数组批量读取；工作台外部 Agent 使用 `get_workspace_context(skills_ids: [...])`。非工作台场景使用 `get_skill(id, resource)`。`skills_task:all` 显式返回所有正文，普通任务不应默认使用它。

`get_skill` 输出契约同时接受入口 `{id,name,content}` 与资源 `{id,path,content}`。同一消息链共享已读取状态，正文不重复注入；读取受整体预算约束，不能在业务循环中重新计算一套预算。

`missingRequiredIds` 检查入口与显式请求的资料，不能证明模型已遵循规则。外部 Agent 选择 prompt / preview / inpaint 后取得对应完整入口；组合示例、用户包与场景模板仍支持冻结补读。正文已离开当前上下文时需重读，不能把目录当成正文。查询预算结束后应根据现有证据作答，说明未核实内容，不自动生图。

## 随附黑白漫画模板

`skill-templates/nai-manga-prompt-design/` 独立于 `skills/`，随安装资源发布；不直接加入内置规则、启用列表或初始上下文。用户通过「随附场景模板」查看并复制，副本默认关闭。已有用户副本保持原样，使用更新后的模板需重新复制并选择启用。

模板的输入组织与评估、动作与连续性、格框、镜头、黑白画法与线效、文字与对白、完整示例全部放入 `SKILL.md`，复制并启用后一次交付。页内主题与技法索引用于定位，不要求调用补读工具。编号只用于执行流程；技法、参数与画师示例按任务和用户选择使用，不因为全文提供而全部套用。92 个代码块与 71 个技法/实例标题保留，完整组合中的语法及空间顺序修订单独登记。

随附模板支持从个人目录删除，删除选择写入用户设置，后续升级不重新添加；安装资源由安装器维护，不直接删除安装目录文件。

## 维护边界

完整提供内置规则用于消除核心资料漏读这一环节，不保证模型逐条遵循或成图达标。没有行为验证前，不因入口变长而重新拆分必要规则。上下文字符数、token、费用和耗时只作诊断，不能替代字段保真与实际任务结果。

内容保全、包内链接、稳定标识、复制导出、冻结读取与 MCP 输出契约由现有测试覆盖，入口见 [验证说明](testing.md)。真实模型的场景选择、最终字段保真和画面质量需要另外验收，不能用可解析响应或离线字符数替代。

回归不设置入口必须缩短到旧版某一百分比的门槛；体积只记为诊断数据。内容修订保留历史指纹，并单列修订原因及替代段落指纹，不通过整体刷新基线掩盖规则删除。真实对照应固定模型、思考设置、输入、工具和规则正文，分别改变按需/全文加载与编号/无编号；历史不同轮次或不同模型配置不能直接合并成成功率。

测试报告、截图、原始响应、规则对照快照与运行日志统一保存在项目外；本文件只维护当前设计，不累积历次执行结果。

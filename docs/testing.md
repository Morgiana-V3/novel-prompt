# 本机开发验收

## 当前规则

用户于 2026-11-06 明确要求：所有后续运行验收直接连接当前本机开发实例，使用现有配置与现有数据。不得使用独立临时 profile、模拟供应商、假图片或合成性能数据替代真实开发测试。项目长期约定见 [AGENTS.md](../AGENTS.md)。

格式、ESLint、Stylelint、类型、依赖边界和静态接口检查仍执行；这些静态检查不代表功能验收通过。历史 fixture 源码保留用于追溯，不再默认执行，也不能作为当前验收依据。

验证范围与改动匹配。纯布局、文案、动画、缩略图展示及不改变业务语义的界面导航，执行相关静态检查，并在当前真实开发窗口定向验证；不得自动扩大到全量灰度、内置 AI 调用或追加生图。涉及生成、计费、存储、MCP 契约、AI 上下文或业务执行链路时，才按受影响范围扩展真实测试；用户要求完整验收时执行全量。涉及 MCP、AI 或工作台业务执行链路的完整验收包含自动灰度和外部 Agent 亲自接入两部分，只运行内置 AI 脚本不能替代后者。

## 验收入口

- `npm run check:quick`：静态检查、接口文档/测试登记检查，再连接当前开发宿主执行只读 MCP 核对。
- `npm run check:full`：静态检查及当前开发实例上的自动真实灰度部分。会真实消耗 AI 接口用量和 NovelAI 额度，不自动更改权限配置；涉及 MCP、AI 或工作台行为时，脚本通过后仍须完成下述外部 Agent 交互验收。
- `npm run live:smoke`：直接运行当前开发实例的自动真实灰度部分，同样不能替代外部 Agent 交互；`npm run mcp:performance-smoke`：对现有工作台进行只读性能采样，不创建大规模合成数据。
- `npm run build`：独立的生产编译检查。当前开发宿主由 `npm run dev` 管理，验收不覆盖 `out/` 后假定旧进程已加载新代码，也不强杀宿主。
- 注册表位于 `scripts/check-cases.mjs`；`scripts/check.mjs` 执行当前验收入口，历史场景名会明确拒绝，而不会悄悄回到模拟测试。

验收前先确认当前实例属于本项目、使用 development 模式、数据目录和加载代码正确；如实例未启动、权限未开启或用户正在编辑/执行任务，应报告具体状态，不通过创建替代宿主、修改真实凭据或绕过编辑锁完成测试。

## 外部 Agent 交互验收

由执行本次任务的外部 Agent 通过应用公开的 MCP 工具真实接入当前开发实例。使用当前配置与现有数据，先读取实际工作台上下文、提示词、当前版本及相关操作记录，并亲自查看实际图片。工具目录只能确认可用接口，不能代替上下文读取和图像观察。

Agent 根据读到的内容与看到的画面自主判断问题，提出具体方案及理由，再通过应用的前台链路呈现、采纳并执行。界面应能看到对应方案、采纳状态、任务进度和结果版本；支持 `step_delay_ms` 的操作设置适当间隔（本轮使用 2000 毫秒），便于观察实际交互。不要用预先写好的固定回答冒充 Agent 的判断，也不要把仅调用内置 AI 或后台脚本执行称为外部 Agent 已体验链路。

执行后重新读取操作与版本记录，查看真实生成或编辑后的 PNG，结合原图判断结果是否符合方案，并核对前台显示与实际保存结果。涉及收费分支时按当前权限真实执行，记录前后额度；遇到未知结果沿用禁止自动重试的规则。

验收报告分别标明自动灰度和外部 Agent 交互的结果，至少保留实际使用的工具、操作编号、工作台与来源/结果版本、前台过程或截图、真实 PNG 路径与尺寸/哈希、额度变化，以及亲自接入时发现的上下文、采纳、执行或结果反馈问题。未完成任一必要部分时明确写出未完成的范围，不能仅凭 `check:full` 退出成功宣称完整验收通过。

## 上下文与画面对照验收

- 核对用户消息的冻结 `inputContext`、同一请求的规则全文及回复的 `requestId`。生成、切换候选或后续编辑后再次读取，原请求的目标、讨论图、修改底稿、参数、规则目录和历史范围应保持原值；不能拿当前状态补作历史输入。查看本轮输入须展示对应请求，旧记录缺失时明确说明。
- 修改底图、讨论图、参考图和区域示意图分别保留角色及版本说明。同一请求内的相同编码图片只装配一次字节，不能因去重丢失用途；缺图与纯文本降级必须明确记录，不宣称模型已经看过或理解画面。
- 图片已装配不等于请求已提交。检查 `prepared`（仅准备）、`attempted`（通过本地检查和授权后进入网络尝试）、`responded`（有效供应商消息返回），并核对累计 `attempts` / `responses`。部分装配失败不能留下已包含标记；请求前取消、缺少 Key 或授权失败不能计实际尝试。HTTP 鉴权失败可能已有网络尝试，但不能计有效回复。文本降级须在序列化前同步图片状态及派生字段；外部客户端没有投递证据时不推断这些阶段。
- 外部 Agent 只有实际通读且正文仍保留在当前上下文时，才能通过 `skills_digests` 显式声明保留。核对 selected/sent/reused/missing 字符数；目录和连接投递缓存都不能代替正文。主动以空保留声明或 `skills_mode:full` 验证正文恢复及 digest 一致性。无状态模型的每次请求仍须携带本轮所需的完整文本，不把本地去重或供应商缓存当作模型记忆。
- 画面优化先亲自看图，记录可见身份特征、服装、道具、人物关系及构图，把应保留项写入方案，再进行有限次数的同种子原版/优化对照，并记录其他参数差异。逐项区分改善、未改善与退化；出现连续性丢失、裁切未解或目标未达时，保留失败结论，不计为优化成功，也不通过反复生图挑选结果掩盖问题。接口成功、真实 PNG 与合法方案只证明链路执行，不能保证画面质量。

## 精修配置与位置展示验收

- 在当前真实开发窗口核对「编辑配置」入口位于左侧工具栏右端；编辑在左侧展开，右侧 AI 对话保持可见；原入口切换为等长的「保存配置」，四字文案等宽；无修改时不预留数量空间，有修改时数量随按钮平滑展开，减少动画偏好下直接切换，底部不重复提供编辑/保存按钮。标签切换成功保存后才离开编辑，失败保留草稿；直接生成先保存配置。
- 打开工作台默认展开版本历史；进入、保存配置不得自动隐藏，编辑期间可收起/展开侧栏。点击历史候选先保存当前草稿，浏览不改变蓝本；保存失败保留草稿。
- 「本版图片」横图/竖图均完整显示，与图集缩略图同样采用方形 contain；收藏和删除在鼠标离开且失焦后隐藏，悬停或键盘聚焦显示。
- 「生成记录」只读文本可选择复制，不出现可编辑表单；检查实际生成记录与起始稿的提示区别。修改下一版后，历史版本的提示词、参数及角色位置保持原值。
- 使用真实生成的多角色版本检查位置列表及可视化布局；「修改对比」检查指定来源 → 正在查看的方向、自动/明确位置变化、增删条目及无位置变化。角色按条目顺序对应，不声称图中位置由视觉识别获得。
- 位置对比弹窗左右分别使用对比对象与正在查看版本的图片和画幅比例，坐标叠在各自的完整图片上；支持隐藏底图，单侧加载失败不影响另一侧和位置记录。生成记录中的单图位置布局也显示对应版本图片；共用参考图的创作/收藏调用仍保持兼容。

## 真实数据与收费证据

工作台输出验收须同时检查正常费用默认收起、未知费用/失败/中断明确显示、操作记录展开与原消息定位，以及候选按钮只浏览、不暗中采纳。一次执行只新增一条结构化结果；全量读取、MCP 摘要和前台状态中的版本及费用字段应一致。模型历史的常规回执筛除数量单独记录，不能计入窗口裁剪数量；原消息与旧冻结输入仍可追溯。正常非零费用也应可在详情查看，不能以简洁为由删除。

自动真实灰度在每次生成后检查费用状态；若未知，先保存操作记录、图库和余额核对结果并停止后续付费步骤。新的余额查询不能追溯证明该次收费。批次中途请求失败时，前几张已知费用也不能冒充整批已核清；不通过故障注入或伪造回执制造真实验收通过。

在现有开发数据中创建带时间戳测试标记的新工作台、标签和生成结果。已有作品和配置保留；不执行清空统计、删除作品、恢复出厂或覆盖安装等会影响既有数据的动作。测试结束保留新测试作品便于核验，清理需明确范围。

灰度通过真实 MCP 调用覆盖优化、画面推测、V4.5 / V5 生图、识图重绘方案、重绘、精修、扩图、收费放大和前台讨论/采纳/生成。核验 PNG 解码与 CRC、尺寸、SHA256、实际落盘、新版本、选区外像素保持及前后余额。同操作编号的显式重放只验证返回既有结果，不允许再次生图；未知结果的写入/付费请求不自动重试。

日志和报告可存放系统临时目录，这只是报告目录，不是另一个应用 profile。报告须记录真实宿主与数据位置、成功和失败步骤、操作编号、图片证据、实际余额及限制；不得复制或输出密钥。验收只断开自己的客户端连接，不退出当前开发应用，不删除真实设置。

## 自动防止漂移

- `contracts` 以 TypeScript AST 核对 IPC/事件共享契约、实际注册声明与架构文档。
- 当前宿主的 `tools/list` 与架构文档双向核对，包含工厂注册的 MCP 工具，不靠工具名字正则猜测。
- `tests:registration` 追踪真实 import/require 依赖，检查测试文件是否有入口或显式历史归属；新文件漏登记会失败。
- `reverse:artist-mix` 是纯计算检查（quick / full 都会运行）：反推画风组成估算的概率融合、单一 / 混合判断、权重映射与自动优化变体生成；不调用模型、不生图，不能代替真实反推与试图验收。
- `boundaries:check` 强制 creation / prompts / artists 等已整理模块的公共入口，拒绝从跨功能调用者直连内部实现及公共入口的通配转导出。

## 完整反推的定向真实验收

在当前开发实例检查 runtime 与加载构建，读取真实图库和原图后，通过 ui_load_reverse_image → ui_compose_reverse_prompt 核对同一次操作得到 desktop.reverse.localResult 和完整 draft；一条失败应保留另一条结果。界面不再出现独立模型选择、反推要求或完整提示词的生图参数/预览。模型直接跟随全局，反推过程中切换时不得采纳旧模型稿。未准备本地模型时仍可反推完整提示词并明确报告画师缺失。

外部 Agent 亲自 read_image、读取 prompt_guide 并检查标签，根据真实画面提交 ui_propose_reverse_prompt → ui_adopt_reverse_prompt → ui_transfer_reverse_prompt（step_delay_ms=2000）。检查新生图标签携带完整主提示词、负面词、角色/位置和可选画师串，已有创作保留；transfer 不应新增生成任务或消耗生图额度。实际生图使用既有生图页及其共享执行链路，执行时保留真实 PNG、操作编号与 Anlas 变化。禁止用静态检查代替运行验收，不覆盖用户反推草稿。

只读反推结果：使用已有真实结果检查主提示词、负面词、角色与位置为可选择复制的文本，不出现文本框、角色增删、位置编辑或本地标签切换。角色详情直接展示，画师候选和反推说明不需展开；只有识别设置与原始分数保留折叠，画师选择与带入生图继续可用。此项为展示验收，不追加 AI 反推或生图。
